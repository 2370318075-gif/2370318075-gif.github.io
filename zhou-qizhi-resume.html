Stream Ready · 浏览器端 AI 母带工作台产品负责人 · 火星超频 Nyro
2026.07 — 2026.11

面向非专业音乐人的 AI 母带工作站：上传成品混音即得自动母带，再用自然语言对话或旋钮精修，导出可直接发行的文件；DSP 全部在浏览器/本机执行，"音频不出本机"是写进界面的产品承诺——支撑 stream-ready.com 正式运营并接入 Stripe 计费。

1. 核心链路设计：上传 → 自动母带（冻结 V1）→ 源诊断卡 → Chat 对话精修 → EQ/宏旋钮微调 → 四轨分离 → 平台响度预览 → 导出/发行打包。上传后由"测量 → 自适应计划"生成保守可复现的母带起点，"源诊断卡"逐条解释这条混音需要什么处理（低频过量/中频浑浊/高频刺耳等），让自动结果可理解、可接管。

2. Chat 改混音的完整链路：用户一句自然语言 → 服务端规划路由携带指令与当前母带状态发给模型 → 模型返回严格 JSON 工具调用（apply_mix_patch 信封）→ 客户端校验参数并翻译成确定的 DSP patch → 就地换母带、播放不中断。每轮发给模型的只有文字与数值：指令、Integrated LUFS / True Peak / 动态范围 / 频段诊断、版本账本与近 20 轮对话摘要——音频波形永不离开本机。

3. 模型接入与降级策略：经 aiHubMix 网关聚合多模型，主用 gemini-3.8-flash、规划超时或不可用自动切换 deepseek-v4.1-flash 兜底；服务端单次规划预算 18s 按模型循环重试，客户端 20s 看门狗 + 40s 硬预算，失败按超时/限流/模型不可用分类透出可读提示，而非整轮卡死。

4. AI 边界与信任设计：模型能力圈在 15 个白名单工具内（改混音/读状态/分段分析/版本恢复/历史查询等），越界请求拒绝而非猜测；每轮编辑强制提交"意图计划"并校验六类否定约束（不要压缩/不要加宽/保留音色…），违反即拒绝并说明原因；每次成功编辑沉淀为版本账本（Chat V1/V2… 可任意恢复），与旋钮层的 3 步撤销相互独立。

5. 关键取舍——确定性优先的双通道：能靠规则算准的指令（分离/增益/带 Q 的 EQ/LUFS/宽度/Warm Tape/版本恢复）走确定性正则直连、零模型调用，不受模型波动影响；含审美判断的复合指令才交回模型——核心链路永不被上游 503 拖垮。

6. 自研 DSP 工具体系（监听 = 交付）：Master EQ 六旋钮（输入/响度/输出增益 + 低中高三段）+ 宏旋钮 Color（6 kHz 搁架 × 磁带饱和）、Air+MidAir（自研动态空气段，包络跟随做程序相关抑制，50 档逐位直通）、Calm（8 带动态共振抑制，只削高出邻域包络的凸起）。实时试听与离线导出共用同一 AudioWorklet 处理器——"听到的就是导出的"；测量按 BS.1770-5 K-weighting 标准；导出 WAV/MP3/FLAC 全部浏览器本地编码（24/32-bit + TPDF 抖动），音频不上传。

7. 四轨分离双路由：人声/贝斯/鼓/其它（htdemucs v4）。云端走自建 RunPod Serverless GPU 端点（RTX 4090；R2 分片上传 8 MiB 逐片 sha256 校验 + 断点续传；仅在提交任务时才唤醒 GPU 冷启动控成本；音频对象 30 分钟 TTL 自动清理）；本地走 Apple Silicon 引擎（一次性配对密钥 + 协议握手 + Origin 白名单），音频不出本机、零云端费用；"本地"关键词由确定性路由识别，不经过模型。

8. 商业化与交付：设计免费额度与付费墙边界、额度计量与导出计费规则并接入 Stripe；主导 v1–v50 高频迭代、每版可回滚，完成从 PRD 到上线运营的 0→1 闭环。
